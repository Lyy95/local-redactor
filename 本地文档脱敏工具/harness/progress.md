## 二、用户需求沉淀

### 1. 核心目标

- 原始资料可能涉密，不能上传外部 AI；先在本机完成脱敏，再将脱敏副本交给 AI 分析。
- 首版至少支持 Word `.docx` 和 Excel `.xlsx`。
- 脱敏后仍要看得懂业务角色、关系、事件顺序和数量级，不能全部替换为无意义内容。
- 每次必须生成密码加密的 XLSX 脱敏映射表，方便后续对应还原。

### 2. 识别范围

- 姓名、身份证号、手机号、地址、车牌、账号。
- 单位、部门、项目、系统名称。
- 地点、时间、金额、案件编号、设备编号。
- IP、域名、内网地址、邮箱、用户名。
- 图片中的文字、印章、签名、二维码、照片和人脸候选。
- 文件属性、作者、修订记录、批注、隐藏文字。
- 页眉页脚、水印、附件、嵌入对象、超链接、隐藏工作表和隐藏行列。
- 多个普通字段组合后形成的可识别信息。

### 3. 界面和操作

- 界面必须简洁、优雅、低文字密度，固定为 `选文件 → 自动检查 → 确认处理 → 生成文件`。
- 第三步使用 `采用建议`、`修改`、`保留原文`、`删除` 等直白操作。
- 提供 `采用全部普通建议`，但图片、低置信度、组合风险和未知对象必须保留人工确认。
- 每次操作要立即反馈、更新剩余数量并进入下一项，不能点击无反应。
- 主界面不得出现内部策略术语。

### 4. 长期规则库和判断标准

- 支持沉淀固定替换，如 `公安 → GA`、`网警 → WJ`。
- 支持可复用判断标准和正确示例，如 `530网 → 5**网`。
- 用户提供的 `jz`、`qb` 等代号原样使用，不擅自解释。
- 支持规则新增、编辑、启停、删除、CSV/XLSX 导入和空白模板导出。
- 规则必须长期保存在当前 Windows 用户的本机加密规则库中，关闭程序后仍存在。
- 导入冲突时必须选择 `保留现有规则`、`采用导入规则` 或 `取消导入`。
- 点击 `以后都这样处理` 后保存长期规则，并在当前已解析文字和 OCR 缓存上增量应用。

### 5. 强制处理要求

- 用户确认属于涉密或必须隐藏的内容，必须改成代号、星号形式或删除，不能保留完整原文。
- 强制规则必须禁止 `保留原文`。
- 只改大小写、添加符号或后缀但仍包含完整原词的替换必须被阻断。
- 同一实体跨正文、表格、工作表和图片 OCR 使用同一代号。
- 组合风险不能由一键操作间接关闭，必须单独确认。

更完整、长期有效的产品和工程约束见根目录 `AGENTS.md`。
