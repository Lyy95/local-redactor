# 本地文档脱敏工具 — 第二轮问题记录与修复方案

日期：2026-08-07

---

## 问题 1：规则没有生效（如"公安"没改成"GA"）

**现象**：用户通过"以后都这样处理"保存了固定替换规则（如 `公安 → GA`），但重新扫描后，"公安"并没有被替换为"GA"。

**根因**：
有两层原因：

### 1a. 规则局部命中与 NER 检测的冲突
在 `service.py` 的 `_apply_text_rules()` 中，当规则命中位置（如"公安"，位置 0-2）与 NER 检测位置（如"公安局"，位置 0-3）**部分重叠但不完全覆盖**时，代码走的是 `_merge_rule_metadata()` 分支（第 767-773 行），仅仅是**把规则信息合并到原 NER 候选的 metadata 中**，而不是用规则替换掉原候选项。

结果：
- 原 NER 候选"公安局"仍然是 PENDING 状态
- 规则的替换值"GA"只在 metadata 的 `rule_id`、`rule_name` 等字段中
- 用户确认时，transformer 按自己的逻辑生成替换值（如"机构甲"），**忽略了规则指定的"GA"**

### 1b. "以后都这样处理"后的流程断裂
`_remember_selected_rule()` 在保存规则后调用了 `reset_task()`（window.py 第 1533 行），清空了所有状态并跳回第一步。用户需要重新勾选边界确认框、重新开始检查。体验割裂且容易误操作。

**修复方案**：
- **1a**：修改 `_apply_text_rules()` 中部分重叠的处理逻辑。当规则与 NER 候选部分重叠时，不应仅合并 metadata，而应将 NER 候选**拆分为规则命中部分和剩余部分**，规则命中部分直接应用规则替换，剩余部分作为独立候选继续复核。
- **1b**：保存规则后不跳回第一步，而是提示用户"规则已保存，需重新检查当前文件以应用新规则"，并自动触发重新扫描。

## 问题 2：同一文件再次处理时仍需重新确认

**现象**：用户对一个文件完成全部确认并导出后，再次上传同一文件，所有候选项重新变为 PENDING 状态，需要再次逐项确认。

**根因**：系统完全没有"任务记忆"机制。每次 `scan()` 都是全新开始——重新 NER 检测、重新规则匹配、从头构建 ReviewBundle。没有任何机制将本次确认结果与文件关联存储。

**修复方案（本次）**：
- 导出时在"本地保管"目录下额外保存一份**脱敏决策快照**（JSON），包含文件 SHA-256 + 每条 finding 的原始值、类别、处理决定
- 下次扫描同一文件（SHA-256 匹配）时，自动加载决策快照，将匹配的 finding 直接标记为已处理，只展示新的/变化的候选项
- 为用户提供"忽略历史、全新检查"的选项

## 问题 3：缺少历史处理结果

**现象**：没有界面可以查看过去处理过哪些文件、处理了哪些内容、导出到了哪里。

**根因**：最初设计中没有历史记录模块。

**修复方案（本次）**：
- 在第一步"选文件"页面增加一个**"最近任务"折叠面板**，列出最近 10 次导出任务
- 每条记录显示：文件名、处理时间、处理了多少项、结果目录链接
- 数据来源：每次导出时在 `%LOCALAPPDATA%\LocalRedactor\本地文档脱敏工具\task_history.json` 追加一条记录

## 问题 4：文档格式丢失（字体、大小、颜色等）

**现象**：导出的 Word 副本中，原来的字体、字号、颜色、下划线等格式全部丢失，只剩加粗和斜体。

**根因**：`DocxAdapter.export()` 完全从空白 `Document()` 重新构建（docx.py 第 799 行），`_write_word_paragraph()`（第 958-979 行）只恢复了：
- 段落样式 ID（Heading 1-9、Title 等）
- 对齐方式
- 加粗（仅当所有 run 均加粗时）
- 斜体（仅当所有 run 均斜体时）

**未保留**：字体名称、字号、字体颜色、下划线、删除线、字符间距、段落间距、行距、缩进、边框、底纹、run 级别的差异化格式（如一段中前几个字加粗后面不加粗）等。

**修复方案（本次）**：
- 在 `_paragraph_style()` 扫描阶段提取更多格式信息：字体名、字号、颜色、下划线
- 在 `_write_word_paragraph()` 导出阶段，对每个 run 单独设置字体格式
- 改为逐 run 导出而非整段统一导出，以保留 run 级别的格式差异
- 保留段落间距、行距和首行缩进

## 问题 5：综合 UX 分析

### 当前应用 UI/UX 存在的问题

#### A. 第一步：选文件
1. **"了解详情与更多设置"默认收起**，新用户不知道可以切换处理模式（保留可读性 vs 隐藏更多细节）
2. **没有最近文件列表**，每次都要通过文件对话框导航
3. **文件拖拽不支持**，只能通过按钮选择
4. **边界确认复选框**位置不突出，文案过于法律化，普通用户可能不理解为什么要勾选

#### B. 第二步：自动检查
5. **进度条阶段描述过于技术化**（"正在本机识别文字、表格与组合风险"），用户不需要知道这些
6. **检查详情表格默认收起**，用户看不到具体识别了什么

#### C. 第三步：确认处理（核心问题最多）
7. **左右分栏布局**导致右侧详情面板利用率低，大量空间浪费
8. **"采用建议 / 修改 / 保留原文 / 删除"四个按钮的视觉层级不清晰**，用户不清楚哪个是推荐操作
9. **预览区域同时显示"原值"和"替代值"**，但没有高亮标注差异
10. **缺少"全部保留原文"**批量操作（如用户判断某类内容全部不需要脱敏）
11. **Tab 标签的数字角标更新不及时**，有时操作后数字不变
12. **图片处理 Tab**：下拉框交互不够直观，框选功能学习成本高
13. **隐藏内容 Tab**：每项都必须单独选择，没有"全部移除"快捷操作

#### D. 第四步：生成文件
14. **预览区域过大**，占用了结果设置的可见空间
15. **结果目录默认值**不够智能（直接用 Documents），应该记住上次使用的目录
16. **完成页的两个卡片**（AI交付、本地保管）视觉对比不够强，用户可能混淆
17. **完成页没有"再处理一个文件"快捷按钮**，必须点"开始新任务"

#### E. 全局
18. **窗口尺寸固定感强**，最小宽度 1180px 在笔记本上偏大
19. **没有暗色模式**
20. **规则库入口不够明显**，且编辑规则库会打断当前任务流程
21. **错误提示不够具体**（如"生成或复扫未通过"不告诉用户哪个环节失败）
22. **没有快捷键支持**（如 Ctrl+O 选文件、Ctrl+Enter 确认等）
23. **步骤条不可点击**，无法直接跳到某一步

### 本次修复优先级

| 优先级 | 问题 | 理由 |
|--------|------|------|
| **P0** | #1 规则未生效 | 核心功能缺陷 |
| **P0** | #2 重复确认 | 严重影响效率 |
| **P1** | #4 格式丢失 | 输出质量核心问题 |
| **P1** | #3 缺少历史 | 用户明确要求 |
| **P2** | UX 改进项 | 体验优化，可分批实施 |
