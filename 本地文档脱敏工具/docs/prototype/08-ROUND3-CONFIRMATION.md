# 第三轮合并修正确认单

日期：2026-08-07  
状态：待用户一次性确认，未修改产品源码。

## 一、本轮目标

在保留现有本机离线、原文件只读、输出复扫和 `AI交付 / 本地保管` 隔离的前提下，完成以下闭环：

1. Word 输出尽量保留原文的版式、字体、段落、编号、页面、表格和图片位置。
2. 用指定文件 `福建省信息化运营管理规范V2.1.docx` 完成实际导出，不再出现“结果未完成”。
3. 判断标准不再是空白页，预置可管理的常用规则。
4. 保留本机加密的历史处理记录。
5. 支持选择文件夹并按队列处理 DOCX/XLSX。
6. 处理中新增或修改规则时，只在已有文字/OCR 缓存中增量计算，不重新读文件、不重跑 OCR、不丢失已完成决定。
7. 图片只将人脸和真正的敏感信息列为待处理项，不再把所有 OCR 文字、普通照片或颜色块都列为风险。
8. 固定规则删除后重启仍保持删除，不再被系统预置自动补回。

## 二、已复现问题与根因

## 三、拟实施方案

### 1. Word 改为“原样式结构 + 安全清理”

- 以原 DOCX 作为版式模板，保留页面尺寸、页边距、分节、样式、编号、字体、段落、表格、图片锨点和相对位置。
- 在原 XML run 上就地替换文字，替代值继承原词所在格式，不再整段重建。
- 继续清除批注、修订历史、隐藏文字、作者属性、自定义数据、外链、OLE、ActiveX、宏、嵌入对象和未允许关系。
- 图片必须重新编码且去元数据；只对确认的人脸和敏感区域打码。
- 导出后仍独立解包、文字/OCR/二维码/关系复扫，不合格继续失败关闭。

### 2. 判断标准预置

向“判断标准”页初始化下列可启用、停用、编辑和删除的本机标准：

- 个人身份：中文姓名、手机号、身份证、银行卡、电子邮箱、固定电话、车牌号、详细地址。
- 凭据秘密：密码/口令/PIN、Token/API Key/AccessKey/SecretKey，均为自动删除。
- 账号网络：账号/用户名、IPv4/IPv6、域名。
- 业务对象：案件编号、设备编号、单位/部门/项目/系统名称、精确地点。
- 判断页直接展示命中方式、处理方式、强制级别、正例和反例，不再只有系统说明页。

### 3. 本机加密历史

- 首页增加“历史处理”折叠区，可查看成功、失败和部分完成任务，并打开结果目录。
- 历史数据使用 Windows 当前用户 DPAPI 加密，保存文件显示名、源文件哈希、加密后的本机路径、时间、状态、数量摘要和结果路径。
- 不保存原文、命中值、映射关系、密码或人工替代内容。
- 支持删除单条历史和清空历史。

### 4. 文件夹队列

- 第 1 步增加“选择文件夹”，默认仅处理当前层，可选“包含子文件夹”。
- 只纳入 `.docx` / `.xlsx`，自动排除 `~$` 临时文件、已生成的脱敏结果目录、隐藏文件和不支持格式。
- 显示文件队列、当前文件、成功/失败/待处理数量。一个文件失败不阻断其他文件，但不将失败项标为成功。
- 每个文件仍有独立复核和输出复扫；高置信强制规则可自动处理，不会为批量速度跳过人脸或低置信敏感项。

### 5. 处理中增量应用规则

- 保存规则后不跳回第 1 步，不清空当前任务。
- 仅使用已解析的文本块和已完成的 OCR 结果执行新规则，显示“已增量应用，新增/changed N 项”。
- 无冲突的已完成人工决定全部保留；只将新命中或与新规则冲突的项目重新打开。
- 任务规则快照更新为当前修订号；不保留“旧规则扫描 + 新规则导出”的混合状态。
- 如果修改的是需要重做 OCR/结构解析的能力开关，界面明确提供“完整重检”，不自动执行。

### 6. 图片筛选与打码

- 自动保留无敏感命中的图片，仍会去除 EXIF/XMP 并重新编码。
- 只列出：人脸；图片中的姓名、手机、身份证、银行卡、邮箱、座机、车牌、账号、密码/密钥/令牌；用户强制规则命中文字。
- 普通 OCR 文字、普通照片、颜色块、普通印章颜色和未命中敏感标准的二维码不进入待处理。
- 打码框按比例外扩并夹到图片边界，打码后对实际图片重跑 OCR/人脸复扫；仅未通过的图片回到图片复核，并显示具体原因。

### 7. 固定规则真正可删除

- “系统内置识别”仍为程序能力说明，不可删除。
- “固定替换”和“判断标准”中的行业/地名/常用预置只在首次或版本迁移时写入本机加密规则库一次。
- 用户删除后不再自动补回；提供单独的“恢复默认预置”入口。
- 删除、停用、编辑后都立即刷新表格和数量，并在重启后验证持久化结果。

## 四、最小操作闭环

### 单文件

`选文件 → 检查 → 处理真正待办 → 中途可增量补规则 → 原样式导出 → 复扫 → 历史记录`

### 文件夹

`选文件夹 → 生成队列 → 处理当前文件 → 导出/记录结果 → 下一个 → 批次汇总`

## 五、验收场景

1. 指定 Word 可完成导出，无 Word 修复提示，页面/分节/样式/编号/表格/图片锨点数量与原文案一致，只有确认的内容和安全对象改变。
2. 指定 Word 中普通图片文字不再生成 13 个待办；真正敏感文字或人脸打码后通过实际媒体复扫。
3. 规则库的判断标准页首次打开即有常用标准，每条都有判断方式、处理、强制级别、正例和反例。
4. 删除一条行业预置和一条自定义固定规则，关闭并重启后都不再出现；恢复默认后只恢复预置。
5. 在第 3 步完成部分决定后新增规则，不出现文件结构/OCR 进度，原决定保留，只新增或更新相关待办。
6. 选择包含至少 3 个支持文件和 1 个不支持文件的文件夹，队列数量正确，每个文件状态和结果可追踪，单个失败不影响后续项。
7. 完成、失败和文件夹批次任务都写入 DPAPI 加密历史；历史文件中搜索不到文档原文或映射值。
8. 文件夹批量、历史、增量规则、单文件和现有 XLSX 闭环同时回归，打包 EXE 自检与 ZIP 校验通过。

## 六、明确非目标
