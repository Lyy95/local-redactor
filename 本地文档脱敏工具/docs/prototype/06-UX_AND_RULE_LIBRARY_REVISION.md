# 极简复核与本地规则库改版确认

Updated: 2026-07-29  
Status: Confirmed — implementation authorized

## 1. 本轮要解决的问题

| ID | 用户反馈 | 当前证据 | 本轮目标 |
|---|---|---|---|
| UX-001 | 界面太复杂、字太多 | 选择页同时展示边界、模式、四类范围；复核页使用 8 列表格、双预览、多个下拉框和三组操作 | 每屏只突出一个任务、一个主操作；说明按需展开 |
| UX-002 | 第 3 步不知道怎么操作 | 主操作叫“确认并应用策略”，并暴露“一致别名、结构模拟、区间化”等内部术语 | 改成用户能直接理解的“采用建议 / 修改 / 保留原文 / 删除” |
| UX-003 | 点击确认有时像没反应 | 当前点击后只更新表格状态和顶部数量，不自动切换下一项，也没有就地成功反馈 | 点击后立即显示完成标记、更新进度、提示结果并自动进入下一项 |
| UX-004 | 需要一键确认 | 当前文字候选必须逐条点击；隐藏对象也逐项选择 | 增加“采用全部普通建议”；安全边界内的项目一次处理 |
| LIB-001 | 敏感词规则要长期积累 | 现有 `TaskTerm` 只支持运行时注入，没有用户入口和持久化 | 增加本机“规则库”，支持手工维护与本地文件导入 |
| LIB-002 | 不只记词，还要沉淀判断标准 | 当前只有词项与类别，没有“何时必须处理、处理到什么程度”的可复用标准 | 增加“判断标准库”，保存条件、处理方法、正反例和强制级别 |
| LIB-003 | 命中的涉密内容必须改成代号 | 当前所有普通候选都可“忽略”，没有强制替换状态 | 命中用户维护的强制规则后禁止保留原文，只能采用或修改代号 |

## 2. 参考原则

本轮参考用户提供的《Claude 5 时代的上下文工程指南：少写规则，多给判断标准》：

- 不堆叠大量禁止性文案，改为清楚的判断标准。
- 标准必须能说明“什么时候适用、正确结果是什么、识别不到时怎么办”。
- 用正确/错误示例校准边界，而不是让系统从大量零散例子里猜。
- 信息渐进披露：当前任务只显示当前需要的操作，详细规则进入“规则库”按需查看。
- 长期标准、当前任务、参考示例分开保存，不混成一个大表单。

## 3. 产品结构

继续保留单窗口四步流程，不增加后台系统或侧边栏。

```text
选文件 → 自动检查 → 确认处理 → 生成文件
```

顶部只保留：

- 当前步骤；
- 当前文件名；
- `本机离线`；
- 一个低干扰的 `规则库` 入口。

移除首页大段检查范围说明、重复边界提示和技术状态堆叠。完整范围放入“查看检查范围”折叠区。

## 4. 四步页面

### 4.1 选文件

主画面只保留：

1. 一个大号文件选择区：`选择 Word 或 Excel 文件`；
2. 默认处理方式：`保留可读性（推荐）`，`更严格`放进“更多设置”；
3. 一行边界确认；
4. 主按钮：`开始检查`；
5. 次要入口：`规则库`。

文件支持范围、完整检查对象和产品边界使用一个 `了解详情` 展开查看，不常驻占用页面。

### 4.2 自动检查

只显示一个进度条和四行状态：

- 正在检查文字与表格；
- 正在检查图片与二维码；
- 正在检查隐藏内容；
- 正在检查组合识别风险。

完成后直接显示：

```text
已找到 15 项需要确认
[开始确认]
```

技术清单放入 `查看检查详情`，默认收起。

### 4.3 确认处理

不再使用 8 列密集表格。主区域改成“待办列表 + 当前卡片”：

```text
待确认 8 项                            [采用全部普通建议]

姓名 · 正文第 1 段
林*河  →  人员甲

系统建议：换成统一代号，前后保持一致

[采用建议]  [修改]  [保留原文]  [删除]
```

#### 点击后的即时反馈

每次操作必须同时发生：

1. 当前项显示绿色完成标记；
2. `待确认 8 项`立即变为`待确认 7 项`；
3. 显示短提示：`已处理，已进入下一项`；
4. 自动选中下一条待确认项；
5. 重复点击不会再次提交；
6. 处理失败时在当前卡片显示具体下一步，不能静默返回。

#### 一键确认范围

按钮文案固定为 `采用全部普通建议`，范围固定为：

- 普通文字和表格候选；
- 用户词库中已有、替换值明确的固定替换；
- 用户判断标准中已有、结果可确定的强制代号规则。

一键确认**不包含**：

- 图片、照片、印章、签名和二维码；
- 低置信度且没有固定规则的文字；
- 组合识别风险；
- 附件、嵌入对象和无法安全解析的对象。

这些项目仍需明确处理，但界面采用同一套简单按钮，不再暴露内部技术名词。

#### 三类复核入口

| 当前入口 | 新入口 | 默认主操作 |
|---|---|---|
| 文字与表格 | 文字 | `采用建议` |
| 图片与二维码 | 图片 | `遮住敏感区域`或`整张移除` |
| 隐藏内容与对象 | 隐藏内容 | `按安全建议移除` |

标签上只显示剩余数量，例如 `文字 3`、`图片 2`、`隐藏内容 1`。

### 4.4 生成文件

保留现有安全闭环和三类产物，但减少文字：

- 上方：原文与副本对照；
- 下方：结果位置和本地映射表风险提示；不再显示密码输入；
- 主按钮：`生成文件`；
- 完成后只显示两张卡片：`给 AI 的文件`、`仅本地保管`。

完成文案继续固定为：

`技术检查已完成，仍需按单位制度确认是否可外发。`

## 5. 用户语言替换

内部枚举和转换算法保持不变，主界面不再显示下列术语。

| 当前术语 | 新界面文案 |
|---|---|
| 一致别名 | 换成统一代号 |
| 结构模拟 | 换成虚构值 |
| 降低精度 | 模糊一些 |
| 区间化 | 显示大致范围 |
| 统一平移 | 调整日期但保持先后 |
| 比例变换 | 调整数值但保持大小关系 |
| 像素处理 | 遮住敏感区域 |
| 转为可见附注 | 保留成普通文字 |
| 忽略候选 | 保留原文 |
| 对照导出 | 生成文件 |
| 全面识别 | 自动检查 |
| 人工复核 | 确认处理 |

通常只显示“采用建议”。只有用户点 `修改` 时，才出现上述易懂选项与替代值输入框。

## 6. 本地规则库

规则库是独立弹窗，只有两个页签：

### 6.1 固定替换

适合明确的一对一替换。

| 原词 | 替换为 | 状态 |
|---|---|---|
| 公安 | GA | 启用 |
| 网警 | WJ | 启用 |

支持：

- `新增`、`编辑`、`停用`、`删除`；
- 从本机 `.xlsx` 或 `.csv` 文件 `导入词库`；
- 下载空白 Excel 模板；
- 在复核卡片点击 `以后都这样处理`，将当前原词和代号保存到规则库。

固定替换命中后自动应用，并归入 `已按规则处理`；用户仍可在本次任务中修改代号。

### 6.2 判断标准

适合保存“什么情况必须处理、怎么处理”的长期标准。

每条标准使用一句话式表单：

```text
当内容 [包含 / 等于 / 符合格式] [条件]
就 [换成固定代号 / 保留首尾并加星号 / 生成顺序代号 / 删除]
示例 [原内容] → [正确结果]
```

最低字段：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 标准名称 | 是 | 用户能理解的名称 |
| 适用条件 | 是 | 精确词、包含词或受控格式 |
| 处理方式 | 是 | 固定代号、星号遮蔽、顺序代号或删除 |
| 强制执行 | 是 | 默认开启；命中后不能保留原文 |
| 正确示例 | 是 | 例如 `530网 → 5**网` |
| 错误示例 | 否 | 帮助说明不应保留成什么样 |
| 适用范围 | 是 | 默认正文、表格、图片 OCR、页眉页脚和隐藏文字全部生效 |
| 启用状态 | 是 | 可停用，不直接丢失历史标准 |

`jz`、`qb`等可作为用户维护的代号输出；程序不自行猜测或展开其真实含义。

## 7. 强制代号判断

工具不能代替单位判断“什么是涉密内容”。强制边界定义为：

> 凡命中用户维护的“强制规则”，或在本次复核中被用户标为“必须隐藏”的内容，必须转换为代号、星号形式或删除，不能选择保留原文。

状态标记：

- `必须替换`：命中强制规则；
- `建议替换`：内置识别候选；
- `需要你判断`：低置信度、组合风险或未知对象。

优先级：

1. 当前任务中用户明确指定的替代结果；
2. 用户固定替换；
3. 用户强制判断标准；
4. 内置类别建议。

当前任务人工修改可以调整代号，但只要命中任一启用的强制规则，就不能改回原文。

同一原词出现冲突时不静默覆盖：

- 完全重复：合并；
- 同一原词对应多个代号：阻止直接导入，并要求选择“保留现有规则”“采用导入规则”或“取消导入”；
- 长短词重叠：优先匹配更长的词；
- 同一实体跨正文、表格、图片 OCR 和工作表时保持同一代号。
- 替换结果不再参加本轮二次匹配，避免 `A → B、B → C` 连锁替换；
- 多个原词指向同一代号时允许保存，但必须提示后续还原可能需要结合位置核对。

## 8. 本地保存与隐私

- 规则库保存在当前 Windows 用户目录，不放在项目目录或任务结果目录。
- 使用 Windows 当前用户级加密保存；其他 Windows 用户不能直接读取。
- 任务保持一份规则快照；处理中修改规则后，在已解析文字与 OCR 缓存上增量应用并刷新快照。
- 规则库损坏、被篡改或无法解密时阻止扫描，不能静默退化为空规则库。
- 不写入应用日志、HTML 报告、AI 分析副本或导出文件属性。
- 导入 `.xlsx/.csv` 只在本机读取；界面用“导入”而不是“上传”。
- 导入文件本身由用户保管，工具不会擅自移动或删除。
- 每次实际命中的原词与代号写入该任务的 `本地保管` 映射表，增加“规则来源/规则名称”列，方便对应核对；整套规则库不会复制进映射表，密码密钥令牌也不进入映射表。
- HTML 报告只记录“应用了多少条本地规则”，不记录规则名称、关键词或替换内容。
- 关闭任务只清除本次文档、明文映射和密码；长期规则库继续保留。

## 9. 状态与操作矩阵

| 状态 | 主操作 | 可选操作 | 结果 |
|---|---|---|---|
| 普通文字待确认 | 采用建议 | 修改、保留原文、删除、以后都这样处理 | 完成并自动进入下一项 |
| 固定替换命中 | 已按规则处理 | 修改代号、停用本次应用 | 不进入普通待确认数量 |
| 强制标准命中 | 采用建议/自动应用 | 修改代号 | 禁止保留原文 |
| 低置信度文字 | 采用建议 | 修改、保留原文、删除 | 必须人工决定 |
| 组合识别风险 | 人工确认处理建议 | 查看关联项 | 即使贡献字段已处理，也必须由用户单独确认 |
| 图片待确认 | 遮住敏感区域 | 整张移除、保留已确认无敏感内容的重编码图片 | 仅敏感命中图片必须决定 |
| 隐藏内容 | 按安全建议移除 | 保留成普通文字、另作任务 | 未决定不能生成 |
| 一键处理中 | 等待 | — | 按可批量范围逐项提交并显示进度 |
| 一键处理部分失败 | 重试失败项 | 逐项处理 | 已成功项不回滚、不重复提交 |

## 11. 变更范围与保护项

允许变更：

- `src/local_redactor/ui/**`
- 新增本地规则库模型、存储、导入和匹配模块
- `src/local_redactor/service.py` 与检测器的规则注入边界
- 对应测试、文档、构建清单与绿色版产物

继续保护：

- 原文件只读；
- 完全离线，无上传、遥测和运行时下载；
- 人脸、结构化敏感信息和强制规则命中图片必须有人工决定；
- 未知对象失败关闭；
- 原版式结构安全副本和实际导出字节复扫；
- 本地映射表与 `AI交付` 分目录，并持续标记严禁上传；
- 不出现“已脱密”“可安全上传”等结论。

## 12. 本轮明确不做

- 不让软件自动判断法律或制度意义上的密级。
- 不增加账号、后台管理、云端词库、联网同步或多人协作。
- 不自动将 AI 返回文档还原成原文。
- 不扩展 PDF、PPT、旧式 Office 或宏格式。
- 不允许一键操作跳过图片、组合风险和未知对象的人工判断。
