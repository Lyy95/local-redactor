# 本地文档脱敏工具 V2 功能清单

## 1. 文档用途

本清单用于回答三个问题：

1. 正式应用应该包含哪些功能。
2. 单文件 DOCX 从入口到结果和历史的流程如何形成闭环。
3. 规则库需要管理什么、如何作用于当前任务。

依据顺序：当前用户结论 → `02-DECISIONS.md` → 需求/字段/状态/验收矩阵 → `DESIGN.md` → UX 原型已固定交互。

标识说明：

- **G2**：Gate 2 单 DOCX 必须完成，未通过前不进入后续阶段。
- **G3**：Gate 2 验收通过后迁移。
- **已确认**：现有文档或 UX 原型已给出明确规则。
- **待确认**：现有依据不足，不得直接实施。

## 3. Gate 2 单 DOCX 任务闭环

### 3.1 闭环主路径

```text
正式 EXE 冷启动
→ 第 1 步：选择真实 DOCX
→ 第 2 步：本机自动检查
→ 第 3 步：逐项确认和手工补充
→ 待处理项清零
→ 第 4 步：生成、落盘复查、目录隔离
→ 写入本地加密历史
→ 关闭 EXE
→ 重新打开后仍可查看历史和结果状态
```

只完成“检测和导出的 Python 调用”不算闭环。必须从打包 EXE 的第 1 步开始，以重启后历史可见结束。

### 3.2 启动与新建任务

| ID | 功能 | 验收要点 |
|---|---|---|
| TASK-001 | 冷启动进入第 1 步 | 未选文件，无虚构当前任务，同时加载本地历史 |
| TASK-002 | 打开 Windows 文件选择器 | 只筛选 `*.docx`；取消不创建任务 |
| TASK-003 | 显示文件摘要 | 真实文件名、DOCX、大小、原文件只读 |
| TASK-004 | 确认处理边界 | 用户确认后才允许开始检查 |
| TASK-005 | 输入阻断 | 非 DOCX、加密/IRM、宏、旧格式、损坏、危险 OOXML 明确阻断 |

### 3.3 自动检查

| ID | 功能 | 验收要点 |
|---|---|---|
| SCAN-001 | Office 包结构检查 | 识别正文、表格、页眉页脚、文档属性、隐藏内容和危险对象 |
| SCAN-002 | 文本敏感信息识别 | 基于本地系统识别、当前任务规则快照和组合风险 |
| SCAN-003 | 图片/OCR 检查 | G2 仅承接引擎已支持的本地检查；复杂图片框选属 G3 |
| SCAN-004 | 检查进度 | 界面显示真实进度/阶段，不用定时器模拟成功 |
| SCAN-005 | 失败与重试 | 失败不进入第 3 步；显示原因、返回和重试入口 |

### 3.4 确认处理

| ID | 功能 | 验收要点 |
|---|---|---|
| REVIEW-001 | 文档真实预览 | 显示选中 DOCX 的可复核内容，原文件只读 |
| REVIEW-002 | 右侧发现列表 | 显示类别、位置、原文摘要、强制状态和待处理数 |
| REVIEW-003 | 建议卡 | 显示原内容、建议结果、引用规则、判断依据和全部位置 |
| REVIEW-004 | 采用建议 | 写入建议替代值，预览、列表和待处理数同步 |
| REVIEW-005 | 修改 | 输入人工替代值，不得继续完整包含强制规则原文 |
| REVIEW-006 | 保留原文 | 需保留理由；命中强制规则时不允许保留 |
| REVIEW-007 | 删除 | 将命中内容设为删除，预览与数量同步 |
| REVIEW-008 | 手工添加脱敏内容 | 内容必须存在于当前文档，添加后进入同一待办列表 |
| REVIEW-009 | 一键采用普通建议并继续 | 只处理可确定的普通项；组合风险、低置信、强制人工项不得越过 |
| REVIEW-010 | 返回上一步 | 已做决定、待处理数和当前任务不丢失 |
| REVIEW-011 | 生成门槛 | 待处理项、图片决定、隐藏对象或阻断问题未清零时不允许生成 |

### 3.5 生成、复查和结果

| ID | 功能 | 验收要点 |
|---|---|---|
| EXPORT-001 | 选择结果保存位置 | 使用 Windows 原生文件夹选择器；取消不伪造结果 |
| EXPORT-002 | 生成 AI 分析副本 | 保留 DOCX 基本结构和语义，应用全部已确认决定 |
| EXPORT-003 | 生成本地映射表 | 包含复原所需映射，持续显示“严禁上传” |
| EXPORT-004 | 生成检查报告 | 只记录技术检查范围、数量、状态和哈希，不含原文/映射 |
| EXPORT-005 | 落盘后复扫 | 复查实际 AI 副本和目录隔离；复查失败则不发布结果目录 |
| EXPORT-006 | 固定目录隔离 | `AI交付` 只有分析副本；`本地保管` 只有映射表和报告 |
| EXPORT-007 | 生成结果反馈 | 只有落盘和复查全部成功后显示完成，并写入历史 |

| ID | 功能 | 阶段 | 验收要点 |
|---|---|---|---|
| HISTORY-001 | 启动时加载本地历史 | G2 | 不需先创建任务；真实历史为空时显示空状态 |

## 4. Gate 3 规则库功能清单

### 4.1 规则库基本原则

1. 规则库是本地持久化数据，不上传、不在线同步。
2. 规则库必须保持 UX 原型的页面结构、Tab、字段、操作、返回路径和冲突处理。
3. 当前任务开始检查时固定一个规则快照，避免复核期间静默变化。
4. 从当前复核项进入规则库后，保存并应用时必须返回原复核项，保留其他已完成决定。
5. 强制规则命中后不允许“保留原文”。
6. 停用规则仍保留，但不参与新的匹配和处理建议。

### 4.2 规则类型

| ID | 类型 | 用途 | 可编辑性 |
|---|---|---|---|
| RULE-TYPE-001 | 固定替换 | 将明确原词统一换成固定代号，适用于单位、项目和约定称谓 | 可新增、编辑、复制、启停、删除 |
| RULE-TYPE-002 | 判断标准 | 保存需要处理的情况、处理方式、正例和反例 | 可新增、编辑、复制、启停、删除 |
| RULE-TYPE-003 | 系统识别说明 | 展示程序自带识别边界和默认处理说明 | 只读，不允许用户修改 |

### 4.3 规则字段

| 字段 | 固定替换 | 判断标准 | 规则 |
|---|---|---|---|
| 规则名称 | 必填 | 必填 | 在复核项“引用规则”中展示 |
| 判断方式 | 必填 | 必填 | 只能从允许的匹配方式选择 |
| 完整原词/判断条件 | 必填 | 必填 | 不允许空值 |
| 处理方式 | 固定为换成固定代号 | 必填 | 决定命中后建议 |
| 固定代号/前缀/示例结果 | 必填 | 按处理方式决定 | 删除、仅人工判断、遮住敏感区域时可不填 |
| 适用范围 | 至少一项 | 至少一项 | 正文、表格、页眉页脚、图片 OCR |
| 正确示例 | 选填 | 必填 | 用于测试和说明命中边界 |
| 反例 | 选填 | 选填 | 用于排除不应命中的内容 |
| 强制执行 | 可选 | 可选 | 开启后命中项不能保留原文 |
| 立即启用 | 可选 | 可选 | 停用后规则仍保留 |
| 版本/修订 | 必须持久化 | 必须持久化 | 任务引用可追溯的规则快照 |

### 4.4 匹配方式和处理方式

**固定替换匹配方式：** `等于`、`包含`。

**判断标准匹配方式：** `等于`、`包含`、`符合格式`、`包含任一关键词`、`同时包含全部关键词`、`仅人工判断`。

**判断标准处理方式：** `换成固定代号`、`保留首尾并加星号`、`生成顺序代号`、`遮住敏感区域`、`删除`、`仅人工判断`。

### 4.5 规则库操作

| ID | 功能 | 已确认规则 |
|---|---|---|
| RULE-001 | 分类 Tab | 固定替换、判断标准、系统识别说明 |
| RULE-002 | 列表 | 显示规则与适用范围、处理结果、状态和操作 |
| RULE-003 | 搜索和筛选 | 按关键词和启用/停用状态筛选 |
| RULE-004 | 新增 | 字段校验通过后本地持久化；可选保存后立即应用当前任务 |
| RULE-005 | 编辑 | 不静默改写当前任务快照；必须明确选择是否增量应用 |
| RULE-006 | 复制 | 使用新 ID 创建副本，原规则不变 |
| RULE-007 | 启用/停用 | 停用后仍保留；不参与新匹配 |
| RULE-008 | 删除 | 需二次确认；不删除任务或已生成结果 |
| RULE-009 | 保存前测试 | 使用虚构/手工输入样例，显示命中与处理结果；不改当前任务 |
| RULE-010 | 单条规则测试 | 输入测试内容，显示是否命中及预期结果 |
| RULE-011 | 导入预览 | 导入前显示可新增、完全重复和冲突项，不直接落库 |
| RULE-012 | 导入重复处理 | 完全重复项自动跳过 |
| RULE-013 | 导入冲突处理 | 同一原词不同结果时，用户选择保留现有/采用导入/取消；禁止静默覆盖 |
| RULE-014 | 恢复缺失默认预置 | 只补齐缺失预置，不覆盖用户规则 |
| RULE-015 | 从复核项查看引用规则 | 传递精确返回上下文，定位引用规则 |
| RULE-016 | 保存并增量应用 | 应用新规则后返回原复核项；保留其他已做决定；新命中项进入待确认 |

### 4.6 规则库待确认项

以下内容在 `docs/prototype` 和 UX 原型中没有完整定义，实施前必须另行确认：

1. 同一内容同时命中固定替换、判断标准和系统识别时的优先级。
2. 多条强制规则结果不一致时的阻断和解决方式。
3. `符合格式` 是只提供预置格式，还是允许用户编写正则表达式。
4. 规则导入的真实文件格式（CSV/XLSX）、列名、版本和错误报告格式。
5. 删除/停用规则是否立即影响当前任务，还是只影响下一个任务。
6. 规则版本回滚、修改历史和操作审计是否进入 V2。
7. 系统识别说明需要展示的类别、字段和版本来源。

## 5. Gate 3 其他功能

| 模块 | 功能范围 | 进入条件 |
|---|---|---|
| 完整历史操作 | 继续未完成、重试失败、查看结果、删除记录 | G2 A–D 硬门槛通过 |
| XLSX | 工作表、隐藏内容、公式缓存值、导出复查 | 规则库与 DOCX 闭环稳定 |
| 文件夹队列 | 成功、失败、跳过、排除、批次汇总 | 单文件状态机和历史稳定 |
| 复杂图片复核 | OCR、二维码、印章、签名、人脸/照片候选、框选遮挡 | 图片安全降级和人工决定规则确认 |
| 最终完整复扫 | 最新规则快照、文字/图片/隐藏对象全量复查 | 各格式和规则引擎稳定 |

## 6. 实施顺序与门槛

1. 先修复 G2 的启动、真实选文件和历史加载。
2. 用打包 EXE 完成一次连续黑盒闭环，关闭重开验证历史。
3. A–D 任一未通过，不实施规则库、XLSX 或队列。
4. Gate 2 通过后，先将本清单第 4.6 节的规则待确认项转成明确决策。
5. 规则库的需求、字段、状态和验收矩阵确认后，再实施 G3 规则闭环。

## 7. 功能清单确认点

请在后续统一确认：

1. Gate 2 是否严格按“EXE 第 1 步 → 真实 DOCX → 四步 → 重启后历史”作为当前唯一实施范围。
2. 规则库是否保留本清单第 4 节的所有 UX 原型功能。
3. 第 4.6 节待确认项是在 Gate 2 通过后集中确认，还是需要现在先定下来。
